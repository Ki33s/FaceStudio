# Режим качества 2.5

По умолчанию используется `quality-v1` из `quality.py`:

- HyperSwap 1a 256 с Pixel Boost 512×512: четыре последовательных прохода.
- XSeg 1 на CPU для каждого заменяемого лица на каждом кадре, включая уверенные
  распознавания. Маска не переносится между кадрами. Размытие границы применяется
  в конечном масштабе кропа.
- Выходное качество FaceFusion 95 и пресет `slow`. Подготовка VFR использует
  x264 CRF 10, вставка исправленного участка — CRF 8.
- Профиль записывается в задание и отчёт. Продолжение обработки пересчитывает
  старые части без нужного профиля. Сборка отклоняет смешение профилей.

Модель замены остаётся 256×256. Pixel Boost не гарантирует восстановление
утраченных деталей исходника. Внешность, резкость и перекрытия требуют просмотра;
проверка восьми кадров не является покадровой гарантией качества.

## Проверка перед выпуском

- Реальный сложный клип: 365 кадров, 800×480, 30000/1001 FPS, 12,18 секунды.
  Сохранены количество кадров, длительность и звук. Обработка заняла 243,64 секунды
  на тестовом компьютере; это один замер, не универсальная оценка скорости.
- В модульной проверке последовательных уверенных распознаваний три входных
  кадра вызвали три обращения к инференсу маски. Проверены размер, тип и диапазон.
- Реальная сцена с несколькими людьми: назначенные лица заменены, неназначенное
  защищено, пустой кадр сохранён. Исправление участка использует хронологию и карту
  движения повторно.
- Проверены пересчёт старой части, повторное использование новой и отклонение
  смешения профилей.
- Проверены подготовка VFR, использование её кэша и вставка участка с сохранением
  звука и количества кадров.
- Оба интерфейса: кнопка открытия, перетаскивание, предпросмотр, перемотка,
  ошибочные файлы, доступность отмены, малое и большое окно.

Число пропусков на сложном клипе не уменьшилось: 27 кадров остаются без замены
около перекрытия рукой и при выходе верхней части лица за кадр. Изменение профиля
улучшает условия рендеринга, но не устраняет эти ограничения отслеживания.
